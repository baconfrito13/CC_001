# 06 · QA and security audit (`qa`)

> **Owner:** `qa-engineer` + `security-auditor` (independent of the builder), fix loop executed by `fullstack-engineer` / `mobile-engineer` · **Inputs:** `<app_dir>/`, `docs/02-product.md` (stories, acceptance criteria), `docs/04-architecture.md` (threat model), `docs/05-build.md`, `legal/public/` + integrated legal pages, `factory/checklists/{security,accessibility,performance,seo,code-quality,launch-readiness}.md` · **Outputs:** `docs/06-qa-report.md` (template `factory/templates/qa-report.md`), regression tests and fixes in `<app_dir>/` · **Gate:** Definition of Done "qa" in `factory/PIPELINE.md` and the QA part of G2: zero open P0/P1, axe zero serious/critical, payments work end to end in test mode, legal pages live in every locale, analytics and error monitoring wired by env vars

## Objective

Try to break the product before a customer does, prove the claims in `docs/05-build.md` with evidence, and drive
defects to closure through a bounded fix loop. Covers functional correctness (every PRD must-story), accessibility,
performance, SEO/consent compliance, security (OWASP ASVS Level 1 oriented), and exploratory testing on real renders.
The report is the evidence for G2; opinions without a command, test id or screenshot do not count.

## Before you start

1. Read `CLAUDE.md`, `factory/LEARNINGS.md`, the PRD stories, `docs/05-build.md` (how to run, flags, seed, known limitations) and the threat model in `docs/04-architecture.md` §11; every H/M threat there must be exercised here.
2. Be independent: do not trust claims in `docs/05-build.md`; re-run everything. The security audit is done by an agent that did not write the code.
3. Test policy: only seeded/test accounts, never real personal data; third parties (Stripe, Resend, Anthropic, analytics) stubbed or in test mode; no live payments, no real emails to real people; `curl` only against your own local/preview URLs.
4. Scratch for artifacts (screenshots, Lighthouse JSON, logs): the session scratchpad, not the repo. Keep only the report and tests in git.
5. Round budget by depth (PIPELINE): lean 1 round, standard max 3, deep max 5 looping until two clean rounds.

## Procedure

### Step 1 — Environment and baseline (round 0)

```bash
cd products/<slug>/<app_dir>
rm -rf node_modules .next && npm ci
npm run check                                              # web starter: lint + typecheck + unit + production build
CHROMIUM_PATH=/opt/pw-browsers/chromium npm run test:e2e   # builds and serves on :3100 itself
npm run start -- --port 3100 >"$SCRATCH/server.log" 2>&1 & # for manual probes, curl and Lighthouse; kill it at the end
```

Record in the report: commit SHA, date, `node -v`, versions of next/react/typescript/vitest/playwright, flags in effect (`payments.live`, adapters). Non-web types: recipe commands (`wrangler deploy --dry-run` + workerd tests, `expo export` + jest, `wxt build` for chrome and firefox + e2e). A red baseline is a P0 "build broken": go straight to the fix loop.

### Step 2 — Traceability and test-pyramid audit

1. Table story id → tests (unit/API/e2e) → result for every PRD must-story and each should-story marked done. A must-story without a passing automated end-to-end test is P1; write the missing test (`tests/e2e/qa-<id>.spec.ts`).
2. Pyramid targets (guidance, judged by risk, not by gaming ratios): ~70% unit, ~20% integration/API, ~10% e2e. Floors: every must-story has ≥ 1 e2e; every API route/server action has tests for success, 400, 401, 403, 404 and 429 where applicable; every webhook has valid, invalid-signature, replayed and duplicate cases; every zod schema has invalid-input tests; the production-safety test (mock adapters refuse to run in production) exists.
3. Coverage (informational, not a quota): `npm i -D @vitest/coverage-v8` if absent, `npx vitest run --coverage`; domain logic dirs (`src/lib`) ≥ 80% lines. Spot-check test strength: break 3 core functions on purpose (flip a comparison, drop a check) and confirm a test fails; restore with `git checkout -- <file>`.
4. Flake check: `npx playwright test --repeat-each=3`; any flaky test is a P2 defect (fix cause: waits, shared data), never retried into green.

### Step 3 — Functional end-to-end of every must-story

For each story: happy path plus ≥ 1 failure path, in `en` and `pt`, at a 390 px and a 1280 px viewport. Mandatory flows:
landing → CTA; waitlist submit (console/webhook adapter) incl. duplicate email and invalid email; locale switch keeps the page; pricing → checkout in **test mode**
(MoR link opens, or Stripe test session + signed webhook fixture updates entitlement; with `payments.live=false` the CTA falls back as designed);
signup/login/logout/session expiry; core value flow; account export and deletion; 404 and error pages; emails produced by the console adapter contain correct links and locale.
Capture console errors and failed requests during every flow (`page.on('console'|'pageerror'|'requestfailed')`): unexpected ones are defects.

### Step 4 — Accessibility (WCAG 2.2 AA)

1. Automated: `@axe-core/playwright` on every route × locale × {390, 1280} px, in default and after-interaction states (open menu, modal, error state, banner):
   ```ts
   const results = await new AxeBuilder({ page }).withTags(['wcag2a','wcag2aa','wcag21a','wcag21aa','wcag22aa']).analyze();
   const blocking = results.violations.filter(v => v.impact === 'serious' || v.impact === 'critical');
   expect(blocking, JSON.stringify(blocking.map(v => [v.id, v.nodes.map(n => n.target)]))).toEqual([]);
   ```
   serious/critical → P1; moderate → P2; minor → P3.
2. Manual (axe finds only a part): keyboard-only walkthrough of each flow (Tab order, visible focus, no traps, skip link, dialog focus management and Escape), 200% zoom and 320 px reflow without horizontal scroll, text-spacing, `prefers-reduced-motion`, forced-colors/dark mode contrast, form errors programmatically associated and announced, one `<h1>`, landmarks, page `<title>` and `lang` per locale, link purpose, image alt. Aid: `await page.locator('body').ariaSnapshot()` to read the accessibility tree.
3. Work through `factory/checklists/accessibility.md`; record pass/fail per item.

### Step 5 — Performance

1. Lighthouse on the landing page of each locale, mobile (default) and desktop. Verified 2026-10-08 with lighthouse 13.5: it has **no `--chrome-path` flag**; set `CHROME_PATH`:
   ```bash
   URL=http://localhost:3100/en; OUT="$SCRATCH/lh"; mkdir -p "$OUT"
   for i in 1 2 3; do CHROME_PATH=/opt/pw-browsers/chromium npx --yes lighthouse@latest "$URL" \
     --only-categories=performance,accessibility,best-practices,seo --chrome-flags="--headless=new --no-sandbox" \
     --output=json --output-path="$OUT/en-mobile-$i.json" --quiet; done        # add --preset=desktop for desktop
   jq -s '[.[]|.categories|map_values(.score)]' "$OUT"/en-mobile-*.json         # take the median per category
   jq '[.audits["largest-contentful-paint"],.audits["cumulative-layout-shift"],.audits["total-blocking-time"]]|map(.displayValue)' "$OUT/en-mobile-1.json"
   ```
   Re-verify flags with `npx lighthouse@latest --help` at execution time. Targets on the landing page: **≥ 90 in all four categories** (mobile emulation, median of 3); desktop performance ≥ 95; LCP ≤ 2.5 s, CLS ≤ 0.1, TBT ≤ 200 ms. 80–89 → P2 with a fix plan; < 80 or any category < 70 → P1.
2. Sandbox noise: a trivial static page scored 87 performance on mobile emulation here (TBT 520 ms, `environment.benchmarkIndex` ≈ 1130). Calibrate against a trivial baseline page, judge by LCP/CLS/TBT and bundle size, and note the calibration in the report instead of chasing noise.
3. Also: `next build` output (First Load JS of landing ≤ 150 KB gzip as a guide), image dimensions/formats, no layout shift on font load, API p95 under 20 concurrent users (`npx autocannon -c 20 -d 15 <url>`, p95 ≤ 300 ms for `api` type), AI endpoints time-to-first-token. Checklist: `factory/checklists/performance.md`.

### Step 6 — SEO and consent compliance (technical)

`factory/checklists/seo.md`: `robots.txt`, `sitemap.xml` (all locales, legal pages), canonical + `hreflang` per locale, unique title (≤ 60) and description (≤ 160), OG/Twitter image renders, JSON-LD validates, 404 status codes, no `noindex` in production, `noindex` on previews. Consent: Playwright test that **no request to analytics hosts or cookies are set before consent**, accept → script loads, reject → none, preference can be changed later, cookie policy lists exactly what is observed. Violations are P0 (illegal tracking) or P1.

### Step 7 — Security audit (OWASP ASVS L1-oriented)

Work through `factory/checklists/security.md` (each item has the command). Minimum evidence:

| Area | How |
|---|---|
| Dependencies | `npm audit --omit=dev --audit-level=high` (exit ≠ 0 fails); `npm outdated`; review new packages' install scripts, licences (no AGPL/GPL), maintainer health (`npm view <pkg> time.modified`); lockfile committed |
| Secrets | `gitleaks detect --no-banner --redact` if installed (not in the cloud image as of 2026-10-08); else `git grep -nIE` patterns over the product and its history (commands below, patterns in the checklist) and the GitHub `run_secret_scanning` tool if available; only `.env.example` is tracked; built assets contain no service keys |
| AuthN/AuthZ | Enumerate routes (build output + file tree). Anonymous → 401/redirect on every protected one; user A cannot read/modify user B's objects (swap ids on every id route: IDOR); role escalation; mass assignment (extra `role`, `user_id`, `plan` fields); logout invalidates the session; OTP/login rate limits; OAuth redirect allow-list; mock auth refuses to boot with `NODE_ENV=production` |
| Database rules | Supabase: the RLS query below must return no rows; per-table two-user + anon tests (select/insert/update/delete) on a local Postgres/PGlite/test project; storage bucket policies; service-role key never in client code |
| Input handling | Payload corpus on every input (very long, unicode, `<script>`, `'"`, `' OR 1=1--`, `${7*7}`, null byte, negative/overflow numbers, extra JSON fields): no 5xx, no reflection unescaped, no SQL error, stored content escaped in both locales; open redirect (`?next=https://evil.example`); SSRF on any server-side fetch (private ranges blocked); file upload type/size; CSRF on cookie-authenticated mutations |
| Rate limits & abuse | 100-request loop (below) at auth, waitlist, checkout and AI endpoints shows 429 past the limit; quota race with parallel requests; AI cost cap and kill-switch |
| Headers/transport | `curl -sI` on `/`, an API route and a static asset: CSP, HSTS (production), `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`, frame protection, no `X-Powered-By`; cookies `HttpOnly; Secure; SameSite`; CORS has no `*` with credentials (`curl -H 'Origin: https://evil.example'`) |
| Webhooks | invalid signature → 4xx; stale timestamp replay rejected; duplicate event id idempotent; tampered body rejected |
| Business logic | price/quantity tampering, negative amounts, coupon stacking, entitlement bypass by calling the API directly, free-tier quota bypass, double-submit on checkout |
| Logging/privacy | no PII/secrets in logs, Sentry `beforeSend`, analytics payloads; error pages hide stack traces; data export and deletion actually remove rows |
| Config | no debug routes, `productionBrowserSourceMaps` off, previews `noindex`, `/api/health` reveals nothing |

Probe commands (run from `products/<slug>/<app_dir>`; `$BASE` = local server or preview URL):

```bash
# secrets: tracked env files, working tree and history (patterns in factory/checklists/security.md)
git ls-files | grep -E '(^|/)\.env' | grep -v '\.env\.example$'                 # must print nothing
git grep -nIE 'sk_(live|test)_[0-9A-Za-z]{16,}|whsec_[0-9A-Za-z]{16,}|sk-ant-[0-9A-Za-z_-]{20,}|AKIA[0-9A-Z]{16}|-----BEGIN [A-Z ]*PRIVATE KEY-----'
git log --all -p -S 'sk_live' --oneline -- . | head                               # history check, repeat per pattern
grep -rEl 'service_role|sk_live|sk-ant-' .next/static 2>/dev/null                 # built client assets: must print nothing
# RLS (run with psql against the local/test database)
#   select c.relname from pg_class c join pg_namespace n on n.oid=c.relnamespace
#   where n.nspname='public' and c.relkind='r' and not c.relrowsecurity;           -- zero rows
# rate limit
for i in $(seq 1 100); do curl -s -o /dev/null -w '%{http_code}\n' -X POST "$BASE/api/waitlist" -H 'content-type: application/json' -d '{"email":"qa'$i'@example.test"}'; done | sort | uniq -c
# headers and CORS
curl -sI "$BASE/" ; curl -sI -H 'Origin: https://evil.example' "$BASE/api/health"
npm audit --omit=dev --audit-level=high; echo "exit=$?"
```

Then run the Claude Code skills on the full product diff: `/security-review` and `/code-review` (`Skill` tool, high effort); add their confirmed findings to the defect log (dedupe, reproduce each before filing).

### Step 8 — Exploratory testing with real renders

1. Script `tests/qa/explore.spec.ts` (kept out of the default e2e project or tagged `@qa`) loops locale {en, pt} × viewport {360×800, 768×1024, 1440×900} × every public route (+ authenticated ones with the mock user), saves full-page screenshots to `$SCRATCH/shots/<loc>-<w>-<route>.png`, and asserts: `document.scrollingElement.scrollWidth <= innerWidth`, no console errors, no failed requests, no text matching `\{\{|lorem|TODO|A PREENCHER|\(placeholder\)|acme\.example`, no identical long strings between locales (untranslated).
2. **Look at the images** (Read tool renders PNGs): clipped or overlapping text, low contrast, broken or missing images, inconsistent spacing, CTA visible above the fold on mobile, brand applied (tokens), empty states, loading states.
3. Timeboxed charters (10 min each, log findings): first-time visitor 5-second test (is the value clear?); hostile input in every form; interrupt checkout (back, refresh, double click, close tab); slow/offline network (`context.setOffline(true)`, `page.route` with delay, 500s); very long names/content; keyboard-only; locale switch mid-flow; expired session; two tabs; browser zoom; account deletion then re-signup; emulated devices (`devices['iPhone 13']`, `Pixel 7`) on Chromium.
4. Known coverage gap: only Chromium is preinstalled; Firefox/Safari and native mobile devices are untested here: state it in the report and add manual device checks to `HUMAN_TASKS.md` when the product type needs them.

### Step 9 — Triage and defect log

Every finding becomes a row in the defect log (report §10): `D-001` · severity · area (functional/a11y/perf/security/i18n/legal/ux/compat) · title · steps · expected · actual · evidence (test id, command output, screenshot name) · round found · status · fix ref · regression test. Group duplicates by root cause. Severity scale:

| Sev | Definition | Examples | Gate effect |
|---|---|---|---|
| **P0 blocker** | Data loss/corruption, exploitable security flaw, legal violation, money taken wrongly, app cannot build/boot/serve | RLS missing on a user table, secret in git or client bundle, authz bypass/IDOR, tracking before consent, checkout charges wrong amount, production build fails, mock auth active in production | Stop. Fix immediately; blocks everything |
| **P1 critical** | A must-story unusable or incorrect, no workaround; serious/critical axe violation on a key flow; high/critical reachable vulnerability; required legal page/locale missing; Lighthouse category < 70 | Signup broken, payment test flow fails, checkout CTA dead, legal page 404 in `pt`, `npm audit` high in a prod path | Blocks G2 |
| **P2 major** | Should-story broken or must-story degraded with a workaround; moderate a11y; Lighthouse 70–89; i18n gaps; missing rate limit on non-cost endpoint; flaky test; layout break on one viewport | Untranslated button, CLS 0.2, form error not announced | Fix per depth; may ship with written rationale and an owner |
| **P3 minor** | Cosmetic, copy nits, minor axe, polish, low-risk hardening | 2 px misalignment, typo, extra console warning | Backlog in report; `docs/10-growth.md` candidates |

Rules: never downgrade severity to pass the gate; when unsure between two levels take the higher; security findings are rated by exploitability × impact, not by how hard they are to fix.

### Step 10 — Fix loop

Each round: (a) run the relevant tests/audits; (b) triage; (c) send the numbered fix list (P0/P1 all, P2 per depth) to the builder agent with reproduction steps; (d) the builder fixes the **root cause** with a minimal diff and adds a regression test for each defect; (e) QA verifies: the failing test passes, then the full unit/e2e suites, then re-runs the audit that found it (axe, Lighthouse, security probe) plus a neighbour sweep; (f) update the defect log and the round history table. The person who fixed is not the one who closes it.

| Depth | Max rounds | Exit when |
|---|---|---|
| lean | 1 | zero open P0/P1; open P2 listed with rationale |
| standard | 3 | zero open P0/P1 and ≤ 5 open P2 with owner and rationale, last round found no new P0/P1 |
| deep | 5 | **two consecutive clean rounds** (no new P0–P2, nothing open P0/P1) and ≤ 2 open P2 |

If the round limit is reached with open P0/P1: (1) hide the offending non-must feature behind a flag (documented deviation) and re-verify; (2) descope with a PRD note; (3) otherwise do not pass: `python3 factory/scripts/factory.py set-phase <slug> qa blocked --summary "<defects>"`, add founder decisions to `HUMAN_TASKS.md` if needed, report to the orchestrator. Never weaken or skip tests, never mark verified without re-testing.

### Step 11 — Cross-checks and G2 inputs

Fill the QA-owned rows of `factory/checklists/launch-readiness.md` (pass/N/A with evidence). Confirm for G2: legal pages in every locale reachable from footer, analytics and Sentry wired and inert without env vars, payments e2e in test mode (or the monetization path configured), `docs/09-launch.md` runbook exists in draft (if not, flag to `devops-engineer`), no `[A PREENCHER PELO FUNDADOR]`/`(placeholder)` in a production build unless it is an open founder task listed in `HUMAN_TASKS.md`. Deep depth: `devils-advocate` pass "how would this embarrass us on launch day?".

### Step 12 — Report and close

Write `docs/06-qa-report.md` from `factory/templates/qa-report.md` (pt-PT): verdict, environment, results per layer, traceability, a11y, performance (median table), SEO/consent, security findings with ASVS area, exploratory findings, defect log, rounds, residual risks and untested areas, G2 checklist. Then `python3 factory/scripts/factory.py set-phase <slug> qa done --summary "<rounds> rounds, P0/P1 open 0, axe 0, LH <min>"` and `factory.py validate <slug>`. Kill background servers. Orchestrator commits `<slug>: qa — …`.

## Depth: lean / standard / deep

| | lean | standard | deep |
|---|---|---|---|
| Functional | every must-story happy + 1 failure path | + should-stories done, both locales, 2 viewports | + cross-device emulation, long-running soak of key flow |
| A11y | axe on all routes, keyboard pass on main flow | + manual checklist, zoom/reflow, SR tree review | + full checklist with evidence per item |
| Performance | Lighthouse landing en | landing both locales + pricing, desktop + mobile, median of 3 | + all public routes, API load test, bundle budget enforcement |
| Security | audit, secrets, headers, authz/IDOR, rate limits on auth | full table above + `/security-review` | + second independent auditor, abuse-case scripts, dependency licence review |
| Exploratory | screenshots 2 viewports, 3 charters | 3 viewports, all charters | + hostile-user charter set, chaos (kill adapters, 500s) |
| Rounds | 1 | ≤ 3 | ≤ 5, two clean rounds |

## Decision rules & defaults

| Topic | Rule |
|---|---|
| Axe | 0 serious/critical on all routes/locales/viewports; moderate ≤ 3 open each justified |
| Lighthouse (landing, mobile, median of 3) | ≥ 90 in performance, accessibility, best-practices, SEO; accessibility and SEO should be 100 on a static page |
| `npm audit --omit=dev` | any high/critical in a reachable prod path = P1 (P0 if exploitable now); moderate = P2; dev-only = P3 |
| Secrets | any real secret in git history or client bundle = P0 (rotate via founder task even if repo is private) |
| Missing RLS/authz | P0; missing rate limit on auth/forms P2; on LLM/costly endpoints P1 |
| Missing security header | CSP/HSTS absent in production P2; others P3 |
| Test flakiness | zero tolerance; fix cause |
| Third parties | stubbed; payments only in test mode; no real recipients |
| Coverage | no global gate; domain logic ≥ 80% lines recommended |
| Unverifiable item (device, live payment, real email deliverability) | list as residual risk + founder/launch task; never mark pass |
| Product types | mobile: `expo-doctor`, jest, web-export Playwright, device matrix as founder task; extension: Chromium persistent-context e2e (see recipe), manifest permission review; API: contract tests + auth matrix + load smoke; bot: signature/idempotency/quota tests |

## Output specification

`docs/06-qa-report.md` sections: 1 Veredicto (PASS/FAIL, one paragraph) · 2 Ambiente e linha de base · 3 Resultados por camada (unit/integração/e2e counts, coverage) · 4 Rastreabilidade (história → testes) · 5 Acessibilidade · 6 Desempenho (tabela mediana de 3, métricas) · 7 SEO e consentimento · 8 Segurança (tabela ASVS, resultados de `npm audit`, segredos, authz/RLS, cabeçalhos, `/security-review`) · 9 Teste exploratório (capturas, charters) · 10 Registo de defeitos · 11 Rondas de correção · 12 Lacunas e riscos residuais · 13 Checklist G2. Regression tests committed in `<app_dir>/tests/`. Evidence referenced by command, test file or screenshot name.

## Definition of Done

- [ ] Report complete; every claim has evidence; versions, SHA and flags recorded.
- [ ] Every PRD must-story has a passing automated end-to-end test in both locales.
- [ ] Zero open P0/P1; open P2/P3 listed with rationale and owner.
- [ ] Axe: zero serious/critical on all routes × locales × viewports.
- [ ] Lighthouse median ≥ 90 on all four categories for the landing page (or documented, calibrated exception with plan).
- [ ] `npm audit --omit=dev` has no high/critical; no secrets in repo/history/bundle; RLS/authz/IDOR/rate-limit/webhook tests pass.
- [ ] Consent gating verified; legal pages reachable in every locale.
- [ ] Payments verified end to end in test mode (or monetization path configured).
- [ ] Fix-loop rounds within the depth limit; fixes each have a regression test and independent re-verification.
- [ ] `factory.py set-phase qa done` + `validate` pass.

## Anti-patterns

- Accepting `docs/05-build.md` at face value; testing only the happy path; testing only English.
- Letting the builder verify their own fixes; closing a defect without re-running the check that found it.
- Raising thresholds' leniency, skipping or loosening tests, or lowering severity to reach green.
- Screenshots never looked at; axe as the only accessibility test; Lighthouse run once on a noisy host.
- Calling real payment/email/AI services or using real personal data in tests.
- Filing vague defects ("looks off") without steps, expected/actual and evidence.
- Auditing from a checklist without trying to exploit anything (no IDOR swap, no payload run).
- Leaving background servers running or committing screenshots/Lighthouse JSON to git.

## Hand-off

- **launch:** verdict, residual risks, env/flag state tested, items that can only be verified on production (live payment, DNS/email deliverability), rollback notes.
- **legal:** consent/legal findings (tracker mismatch, missing documents) for `docs/07-compliance.md`.
- **builder (fix loop):** numbered defects with repro; after closing, the regression tests stay in the suite.
- **growth:** P2/P3 backlog and UX observations as experiment candidates.
- **founder:** manual checks no cloud session can do (real devices, Safari/Firefox, live payment smoke) as `HUMAN_TASKS.md` entries with exact steps.
